## 🔴 CRITICAL（2 项）

### C1 · 安全 | 云端 manifest 字段未净化 → 任意文件写入（RCE 链路）

`merge.ts:94-108` 对远端记录**零 schema 校验**直接入库；`thumbnails.ts:14-19` 的 `thumbPath()`/`previewPath()` 把原始 `image.id`、`hash` 拼进本地写路径；`engine.ts:306` 的 `safeName` 只净化了 `fileName` 而 `id.slice(-6)` 未净化（`../../` 恰好 6 字符可通过），随后 `ensureThumb` 再次经未净化的 `thumbPath` 写盘。

**利用场景**：控制 MinIO 桶的攻击者（恶意共享端；且 `useSSL` 默认 `false`，链路上也可注入）发布 `id: "../../../../Library/LaunchAgents/com.evil"` 的 manifest，下次同步即在存储根之外写入任意内容，登录时执行代码。

**修复**：在 `fetchManifests` 入口对每条记录做 schema 校验（`id` 限 `^[0-9a-z]+$`、`hash` 限 `^[0-9a-f]{40}$`、`fileName` 过 `sanitizeFileName`）；缓存文件名改由净化后的 id 派生；所有 fs 写入前用 `assertInside(root, target)` 断言路径包含。

### C2 · 性能 | `commit()` 每次变更同步全量重写 `library.json`

`library.ts:189-199` 每次 mutation 都 `libraryStore.flush()` → `store.ts` 的 `fs.writeFileSync(JSON.stringify(data, null, 2))`（美化格式≈2 倍体积），且每次对全库重新归并 tags。`importPaths` 逐图 commit、`markLocalFile` 逐下载 commit、`restoreImages` 在循环体内 commit —— 向 5000 图库导入 500 张 ≈ **1GB 级主线程阻塞 I/O（O(n²)）**，期间所有 IPC、`media://` 缩略图、轮播 tick 全部卡死。

**修复**：`commit()` 改用 JsonStore 已有的防抖 `scheduleSave`（仅退出/错误路径 flush）；批量操作合并为单次 commit；library 存储去美化格式。

## 🟡 MEDIUM（按主题归纳，~30 项）

- **错误处理缺失**：store 全部 action 无 catch（调用侧 `void` → unhandled rejection 无用户反馈）；`SyncSection.reload/patch` 失败整节静默渲染 `null`；`removeObjects` 逐对象错误被忽略、失败计为"已清理 N 个"（`health.ts:94-103`）；`verifyIntegrity` 只 `.catch(() => setVerifying(false))`。
- **竞态**：轮播间隔数字输入每击键发 IPC 且响应可乱序回跳（`SlideshowPanel.tsx:28-34`）；相册创建双击重复提交（`AlbumEditorModal.tsx:58-72`）；下载取消是全局单标志，新批次会"复活"旧取消且 in-flight 传输不受控（`engine.ts:49-54,343`）；两个 `DeleteConfirmModal` 实例可同时打开、Esc 双触发。
- **同步健壮性**：远端墓碑**无上限**应用——一台被攻破设备可让全库记录消失并再传播（`merge.ts:66-75`，建议超阈值暂停+确认）；`sameAs` 对每份 manifest 全量 `JSON.stringify` 比较（≈20MB/次同步）；manifest 拉取串行；每次 `ensureLocal`/缩略图请求新建 `Minio.Client`（FD 抖动）；失败下载泄漏 `.part.minio`；SecretKey 在 safeStorage 不可用时明文 base64 落盘且无警告（`sync/store.ts:42-53`）；`useSSL` 默认 false。
- **轮播**：多屏同一 delay 齐发（N 个子进程 + N 个 sharp 同时开工）；`tickMonitor` 不带 `excludeIds`，顺序模式各屏 lockstep 显示同一张图；`applied/` 预渲染缓存无限增长（可达 20GB+，无 LRU）。
- **数据一致性**：`repairLocalBroken` 原地改记录、不广播 `LIBRARY_CHANGED`、不核验是否真断链（`health.ts:107-121`）；`purgeCache` 批量删除中逐图 readdir（500 张 ≈ 250 万 dirent 扫描）；退出时 `purgeStaging` fire-and-forget 可能被杀。
- **类型系统**：`LibraryFilter.categoryId: string | null | 'all' | 'favorites'` 联合被 `string` 吞掉且漏了 `'uncategorized'`；`SlideshowScope` 非判别联合，迫使 `as` 断言与 `split(':')` 解析；`as never`（`SlideshowPanel.tsx:257`）；IPC payload 契约只在注释中，三端漂移编译器不可见。
- **可访问性**：虚拟网格键盘不可达（无 role/tabIndex/方向键）；右键菜单无 `role="menu"`、Esc 不关；Modal/Drawer 无 `role="dialog"`/焦点陷阱，Esc 一次关全部层；Toast 无 `aria-live`；无 `prefers-reduced-motion`；Lightbox `onWheel preventDefault` 在 React 17+ passive 监听下无效。
- **UX 不一致**：Lightbox 单张删除用原生 `confirm()` + 乐观 toast + 无撤销 + 无"仅清本地"，与 F1 脱节；4 处原生 `confirm()` 应统一 `ConfirmModal`；"存为相册"静默丢弃 keyword/size 条件且创建后不选中新相册；相册计数与筛选结果口径不一致。

## ⚪ LOW（简列）

魔法数字（菜单估高 430、overscan 2、重试 1200ms）；缩略图重试 `setTimeout` 不清理；行高假设 footer 恒 34px 但可换行 → 滚动漂移；死的响应式 `grid-cols-*` 类；死代码（`confirmDelete`、`removeMany`、相册 `editing` 分支不可达）；`isLibraryFile` 大小写敏感；`storage-dir.json` 指针无校验、迁移先写指针后 parse；AppleScript 只转义 `"`；`wallpaper.ps1` 无完整性校验即 Bypass 执行；错误消息带绝对路径回渲染进程；手动"下一张"逐屏串行；`media.ts` 线性 `find`；端口输入 `Number()||9000` 跳变；撤销快照 3 处复制粘贴（DRY）。

## ✅ 做得好的

`contextIsolation:true` + `nodeIntegration:false` 双窗口齐全；preload 固定白名单通道；`media://` 仅 id + 严格正则；双 HTML 均有 CSP；Windows 壁纸走 `execFile` argv 无 shell 注入；删除一律 trash/staging 可恢复；SecretKey 不回渲染进程 + safeStorage；JsonStore 原子写；dev 同步保险丝；虚拟滚动基础设计正确（解析式行高、rAF 节流、稳定 key、lazy）；`matchAlbum` 双端共享；Zustand 不可变更新；`【系统适配】` 注释约定清晰。
